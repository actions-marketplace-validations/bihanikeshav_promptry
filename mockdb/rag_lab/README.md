# RAG Lab — realistic mock production environment

A self-contained mock RAG endpoint for testing promptry against real
LLM traffic. Uses Project Gutenberg books as the knowledge base,
local Ollama models, ChromaDB for retrieval, and 18 simulated user
personas. Everything is local — no API keys, no cloud calls.

## What it produces

- 4 public-domain books vectorised into 649 chunks (~1.5 MB of prose)
- 15 system-prompt variants spanning terse, persona, format-constrained, and adversarial-soup styles
- 318 captured user interactions across 18 personas, 2 models
- Eval results for 5 promptry suites: semantic, llm-judge, grounded, safety, json-format
- A semantic-vs-LLM-judge agreement comparison (Spearman rho) over the cross-product of (model, prompt)
- Cost + latency telemetry per model

## Quickstart

```bash
# Prereqs (one-time):
ollama pull qwen3:1.7b
ollama pull qwen3:4b-thinking-2507-q4_K_M
pip install chromadb sentence-transformers requests

# Stage 1: vectorise the corpus (~15 sec)
python -m mockdb.rag_lab.build

# Stage 2: simulate 318 user interactions (~12 min)
PROMPTRY_DB=mockdb/rag_lab/data/lab.db \
  python -m mockdb.rag_lab.simulate --workers 4 --big-model-share 0.2

# Stage 3: run the 5 eval suites (~20 min — judge calls are slow)
PROMPTRY_DB=mockdb/rag_lab/data/lab.db \
  python -m mockdb.rag_lab.evaluate

# Stage 4: print the cross-product comparison
PROMPTRY_DB=mockdb/rag_lab/data/lab.db \
  python -m mockdb.rag_lab.compare

# Stage 5: print the broader insights report
PROMPTRY_DB=mockdb/rag_lab/data/lab.db \
  python -m mockdb.rag_lab.report

# Browse it all in the dashboard
PROMPTRY_DB=mockdb/rag_lab/data/lab.db \
  promptry dashboard --port 8423
```

## Files

| file | role |
|------|------|
| `corpus/` | 4 public-domain books (Sherlock, Pride & Prejudice, Frankenstein, Federalist Papers) |
| `prompts.py` | 15 system-prompt variants used in the simulation and eval grid |
| `users.py` | 18 user personas with hand-curated question banks |
| `rag.py` | ChromaDB indexer + `retrieve()` |
| `pipeline.py` | RAG pipeline: retrieve → render prompt → call Ollama. Caches every (model, prompt, question) tuple to `responses_cache.json`. |
| `judge.py` | LLM-as-judge using qwen3:1.7b (small judge default; bump to 4b-thinking via `set_judge_model`) |
| `suites.py` | 5 promptry suites: rag-semantic, rag-llm-judge, rag-grounded, rag-safety, rag-json-format |
| `build.py` | Stage 1: index the corpus |
| `simulate.py` | Stage 2: run 18 users × 318 messages with parallel workers |
| `evaluate.py` | Stage 3: run all 5 suites against the lab DB |
| `compare.py` | Stage 4: cross-product semantic-vs-llm-judge with Spearman rho |
| `report.py` | Stage 5: full insights report (suites, captures, prompt versions, cost) |

## What's gitignored

- `chroma/` — regenerable in 15s via `build.py`
- `data/lab.db` — regenerable in 30 min via `simulate.py` + `evaluate.py`
- `data/captures/` — regenerated alongside the DB
- `responses_cache.json` — regenerated by `pipeline.py` on first call
